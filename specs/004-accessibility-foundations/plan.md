# Implementation Plan: Accessibility Foundations — Alt Text, Personal Video Delivery, Localized Errors

**Branch**: `004-accessibility-foundations` | **Date**: 2026-08-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/004-accessibility-foundations/spec.md` (post owner-interview 2026-08-17 — captions removed, two video types, Paymob-only payments, phone-based delivery; §Clarifications binding; supersedes all pre-interview drafts).

## Summary

One forward migration (`0049_accessibility_foundations.sql`) plus small edge-function extensions and forward guard (`0051_storage_objects_rls_guard.sql`) — alters constraints on two pre-existing tables (`announcements.published_at DROP NOT NULL` to allow draft state; `event_outbox_whatsapp_template_check` drop/re-add to permit `video_ready` template), no new enums. Adds: central `media_assets` alt-text registry (path-keyed, content-linked, decorative flag, Arabic-first) with publish-gate RPCs for announcements/priest photos; automated personal-video delivery (`deliver_personal_video`: phone + YouTube URL + title + PAID payment → unlisted video + access grant + one `video_ready` WhatsApp outbox event, idempotent); staff image-backlog with keyset pagination; tenant-scoped Arabic `error_messages` catalog served through a 5-min-TTL cache behind the frozen 003 `respond()` seam (`message_ar` field). Behavior-preserving elsewhere (FR-010).

## Technical Context

**Language/Version**: SQL (Postgres 16 via Supabase) + TypeScript on Deno (edge functions).

**Primary Dependencies**: existing `_shared/http.ts` (feature 003 seam), `event_outbox` drain (0027, 100/batch-10/cron-1min), storage buckets (0044), `users.phone` (NOT NULL UNIQUE — buyer resolution), `video_purchases` (payment-keyed, own-read policy). No new deps.

**Storage**: Supabase Postgres — migration 0049 (2 new tables, 4 new RPCs, 1 view, seeds, policies on new objects, 2 existing table constraint alterations: `announcements` and `event_outbox`) plus migration 0051 (forward counterpart for 0044 hardening).

**Testing**: SQL suite (`tests/0049_accessibility_test.sql`, registered in `run_all.sql`, `BEGIN/ROLLBACK`, explicit fixtures, negative-auth per FR-011); Deno tests (`_tests/messages_test.ts`, extended `http_test.ts`, event-dispatcher `video_ready` case); manual gates in quickstart.md.

**Target Platform**: Supabase (local stack → hosted).

**Project Type**: backend feature (web-service).

**Performance Goals**: catalog cache ⇒ zero DB roundtrip per error after first hit; backlog pages ≤100 rows keyset; no change to booking/payment/catalog paths.

**Constraints**: FR-012 forward migrations only (0049 alters constraints on 2 existing tables additively-in-effect; 0051 covers 0044 hardening edit); FR-009 tenant patterns; RPC privilege hardening; 003 error codes frozen; WhatsApp only via outbox; no caption/transcript metadata anywhere (owner decision).

**Scale/Scope**: 1 migration + test, 1 view, 4 RPCs, 2 tables, `_shared/messages.ts`, `http.ts` extension, event-dispatcher template handler.
