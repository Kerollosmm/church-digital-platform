## 4. Manual Smoke Script (requires local stack: `npx supabase start` in repo root)

> Note: screens may not be reachable in the real app until the GoRouter route wiring lands (see §5 gap 1). This script verifies each screen in isolation (tests) and end-to-end once routes exist.

### Step 1 — Auth (navy glass)
1. Open app → `LoginScreen`. Expected: deep-navy glass card (`AppColors.primaryContainer`), phone field with `+20` prefix, strings `AppStrings.authTitle`, `AppStrings.phoneLabel`, CTA `AppStrings.sendOtpCta`.
2. Enter number → `OtpScreen`: 6 glass OTP boxes, `AppStrings.otpIntro`, `AppStrings.confirmOtp`, `AppStrings.resendOtp`.

### Step 2 — Home hub & tabs
1. After login → `HomeHubScreen` inside `BottomNavScaffold` (glass `TopBar`).
2. Tabs (labels `AppStrings.tabHome` / `tabBooking` / `tabVideos` / `tabComplaints` / `tabProfile`), active tab = gold pill.
3. Quick actions grid (`AppStrings.quickServicesTitle`), announcements carousel (`AppStrings.announcementsTitle`), verse card (`AppStrings.verseText`).

### Step 3 — Booking flow
1. Services tab → `ServicesListScreen` (cards from `v_available_slots`, `AppStrings.priceFrom`).
2. Select service → `SlotGridScreen`: slot cards with chips from `slot_status` — `AppStrings.statusAvailable` (green) / `statusBooked` (grey) / `statusClosed` (red).
3. Select available slot → `BookingDetailScreen`: summary card (`AppStrings.bookingSummary`), countdown banner shows static `AppStrings.completeBookingPrompt` («يرجى إتمام الحجز خلال ٢٠:٠٠ دقيقة»), WhatsApp opt-in checkbox (`AppStrings.whatsappOptIn`), gold `AppStrings.confirmBooking` CTA.
4. Book → success → `BookingTicketScreen`.

### Step 4 — Digital ticket
1. `BookingTicketScreen`: success header `AppStrings.bookingConfirmedSuccess`, ticket card (navy header, solid dividers, QR placeholder — static icon, no real QR), rows `AppStrings.bookingNumberLabel` / `AppStrings.paidAmountLabel` / `AppStrings.createdAtLabel` (rendered only when data present), status chip via `resolveBookingStatus` («في انتظار الدفع» for `PENDING_PAYMENT`).
2. Buttons: `AppStrings.editBooking` (re-enters booking flow), `AppStrings.cancelBooking` (calls `cancel_booking` RPC via repository, pops on success), `AppStrings.backToHome` (pops). No WhatsApp button (omitted by design).
3. `MyBookingsScreen` (`AppStrings.myBookingsTitle`): list rows `AppStrings.bookingNumberPrefix` + id, status chip, `AppStrings.retryPayment` button for `PENDING_PAYMENT` rows; tapping a row opens the ticket.

### Step 5 — Checkout (pay stub)
1. `PaymentRedirectScreen` (`AppStrings.checkoutTitle`): 3 payment-method cards — `AppStrings.cardMethod` / `fawryMethod` / `walletMethod` (visual selection only, informational), shield note `AppStrings.securePaymentTitle`/`securePaymentDesc`, order summary `AppStrings.orderSummaryTitle` showing only `AppStrings.bookingNumberLabel` + `#<id>` (**no amount rows — no amount data on this screen, by design**).
2. Gold `AppStrings.payNow` (busy state while launching) → `fetchCheckoutUrl` → `launchUrl` (external). Failure → SnackBar `AppStrings.paymentOpenFailed`. Terms note `AppStrings.termsNote`.

## 5. Known Gaps & Deferred Items

1. **`/payment-redirect` route not registered** in `lib/app_router.dart` (GoRouter). Screens are reachable only in tests until the router task from the architecture-fixes plan lands. All three callers (`booking_detail_screen`, `my_bookings_screen`, `video_purchase_screen`) push this route name — plan risk note acknowledges "stays until GoRouter lands".
2. **WhatsApp action buttons/banners omitted** plan-wide (ticket, media store, checkout) — no backing RPC. Documented in plan Task 5.
3. **Ticket card uses solid `Divider`** instead of the HTML's dashed rows — cosmetic deviation, noted in Task 5 review.
4. **Checkout order summary has no amount** — the screen receives no price data (only `bookingId` + `checkout_url`); amounts from the HTML are demo-only.
5. **Admin screens from the design zip deliberately excluded** (plan risk note).
